# Slack integration setup

Each agent uses its own Slack app. This gives the agent a dedicated name, identity, conversations, and credentials in every Slack workspace where it is installed.

## How a Slack user is matched to an **auxilia** user

When a Slack message comes in, **auxilia** looks up the Slack user's email via `users.info` and matches it against the workspace's user table. If there's no match, the bot replies with a message telling the user to sign in to **auxilia** first.

Slack users therefore need an **auxilia** account with the same email address as their Slack profile.

## Install an agent in Slack

Open the agent in **auxilia**, find its Slack integration, and select **Connect Slack workspace**. The setup guide provides a Slack app manifest and the callback URLs for that agent.

Create the app from the supplied manifest, install it in the target Slack workspace, then copy its Bot User OAuth Token and Signing Secret back into the agent's Slack connection. Both secrets are encrypted before they are stored.

The generated manifest contains the required scopes, event subscriptions, interactivity configuration, and message shortcut. If the Slack app configuration changes later, use the setup guide again to copy the current manifest.

## Workspace control

Workspace admins can enable or disable all agent-specific Slack bots under **Settings → Messaging**. Credentials remain managed on each agent.

## Which model Slack threads use

Slack has no model picker. New Slack threads start on the workspace default model, or the first available model when no default is configured. See [Workspace default model](/agents#workspace-default-model).
